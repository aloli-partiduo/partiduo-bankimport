= Contrat `Bankimport::Api`
:toc: left
:toc-title: Table des matières
:icons: font

Contrat public de l'extension `BANKIMPORT` (ADR-011 D6), sur le modèle de
`Partiduo::Api` : acteur en premier argument, contrôle d'accès en première
ligne (extension active, permission), vues immuables, commandes qui rendent
un `Result` avec des erreurs par champ (`bankimport.errors.*`), dans une
transaction. L'interface `ui/bulma/` et les extensions qui en dépendent
(`partiduo-perso`) ne passent que par lui.

== Permissions

[cols="1,3",options="header"]
|===
|Permission |Ouvre
|`bankimport.read` |`formats`, `format`, `sample`, `detect_kind`, `imports`, `import_detail`, `import_content` (+ `core.attachment.read`), `lines`, `count_lines`, `line`, `lines_by_entry`, `open_items`, `rules`, `rule`, `tile`
|`bankimport.import` |`preview`, `import_file` (+ `core.attachment.write`), `set_counterpart`, `clear_counterpart`, `discard`, `restore`, `apply_rules`, `transfer` (+ `accounting.entry.post`, journal en écriture), `relink` (+ `accounting.entry.read` ; `accounting.matching.write` si le relevé est refait), `reconcile` (+ `accounting.matching.write`)
|`bankimport.admin` |`check_format`, `create_format`, `update_format`, `delete_format`, `create_rule`, `update_rule`, `delete_rule`, `delete_import`, `purge`
|===

Les lignes et les imports ne sont visibles que dans les journaux financiers
que l'acteur voit (`Partiduo::Api::Accounting.ledgers`).

== Import

* `preview(actor, ImportInput) : Result(PreviewView)` — lit sans écrire :
  genre reconnu, lignes (`duplicate` pour un doublon), anomalies
  (`lines[<rang>]`), import antérieur du même fichier, compte et solde lus.
* `import_file(actor, ImportInput) : Result(ImportView)` — pièce jointe,
  lignes en attente, règles, lettrage proposé, écritures semblables
  signalées. Erreurs : `ledger.blank|invalid`, `file.blank|too_large|binary|
  empty|not_ofx|not_qif|malformed_csv|already_imported|too_many_lines`,
  `format.blank|unknown`, `choice.invalid` ; celles du socle pour la pièce.
* `ImportInput` : `ledger_id`, `filename`, `content` (octets), `kind`
  (`auto`, `csv`, `ofx`, `qif`), `format_id` (CSV), `date_format` (QIF),
  `allow_same_file`.
* Fichier conservé par le socle en `text/csv`, `application/x-ofx` ou
  `application/qif` (D-BKI-014) ; les relevés conservés avant la 0.1.4 en
  `text/plain` ou `application/xml` se relisent de même (`import_content`
  rend le type enregistré).

== Bénéficiaire et IBAN (0.1.4, A-PER-2)

* `LineView#payee` : bénéficiaire de la ligne, lu dans le relevé (OFX
  `NAME` ou `PAYEE`, QIF `P`, colonne « tiers » d'un CSV), remplacé par
  celui d'une règle qui en donne un, ou choisi par l'utilisateur
  (`CounterpartInput#payee` : `nil` garde, `""` retire ; changé, il est
  appris avec la règle). `LineView#iban` : IBAN de la contrepartie (OFX
  `BANKACCTTO`, colonne `FormatInput#iban_column`), forme compacte.
* `RuleInput#payee`, `RuleView#payee` (120 caractères,
  `bankimport.errors.payee.too_long`) ; « le libellé contient » cherche
  aussi dans le bénéficiaire.
* À défaut de règle, la fiche active qui porte l'IBAN lu
  (`Partiduo::Api::Cards::CardQuery#iban`) est proposée, si elle est seule
  et que l'acteur lit les fiches (D-BKI-013).
* Écriture transférée : libellé « bénéficiaire · libellé du relevé », ou le
  libellé du relevé seul s'il contient déjà le bénéficiaire (D-BKI-012).
* `lines_by_entry(actor, entry_ids) : Hash(Int64, LineView)` — lignes
  transférées vers ces écritures (journaux visibles), pour qui présente les
  écritures (`partiduo-perso` y lit le bénéficiaire).
* Tous ces champs sont ajoutés en dernier aux records, avec un défaut.

== Zone d'attente

* `lines(actor, LineQuery)` — filtres : `ledger_id`, `import_id`, `status`
  (`pending` par défaut, `nil` pour tous), `search`, `unassigned_only`.
* `set_counterpart(actor, id, CounterpartInput)` — fiche *ou* compte,
  `match_line_id` facultatif, `learn` (règle apprise). Erreurs :
  `counterpart.blank|both|card_unknown|account_unknown|account_not_direct`,
  `line.not_pending`, `line.match_invalid`.
* `discard`, `restore` (`line.fitid_taken`), `purge`, `apply_rules`.
* `transfer(actor, ids) : Result(TransferReportView)` — une écriture par
  ligne par `post_financial` ; refus gardés sur les lignes (`error`).
* `relink(actor, line_id, entry_id) : Result(LineView)` (0.1.4, A-PER-3) —
  rattache une ligne à traiter à une écriture déjà passée : celle qui
  corrige l'écriture transférée puis extournée de la ligne, ou celle passée
  à la main qu'elle signale. La ligne redevient `transferred`, sans nouvelle
  écriture ; si l'écriture extournée figurait au relevé pointé de l'import,
  ce relevé est défait puis repointé (même référence, mêmes soldes, même
  fichier) avec l'extourne et la nouvelle écriture. Contrôles : ligne à
  traiter (`line.not_pending`) ; écriture lisible
  (`relink.entry_unknown`), ni extournée ni extourne
  (`relink.entry_cancelled`), du journal de la ligne (`relink.ledger`),
  dont le mouvement sur le compte de banque vaut le montant de la ligne
  (`relink.amount`), à 31 jours au plus (`relink.date`), qu'aucune autre
  ligne ne cite (`relink.entry_taken`) ; champ `entry_id`. Les erreurs du
  rapprochement sont rendues telles quelles, et rien n'est changé.

== Pointage

`reconcile(actor, import_id, ReconcileInput(reference, start_balance,
end_balance))` — appelle `Partiduo::Api::Accounting.reconcile` avec les
écritures transférées non rapprochées de l'import. Erreurs :
`reconcile.already|nothing` et celles du rapprochement
(`accounting.errors.reconciliation.*`).

== Formats et règles

`FormatInput` : `name`, `institution`, `ledger_id`, `separator`
(`comma|semicolon|tab|pipe`), `encoding` (`utf-8|windows-1252`),
`skip_lines` (0 à 50), `date_format` (`dd/mm/yyyy`…), `decimal_separator`
(`comma|dot`), `thousands_separator` (`none|space|dot|comma|apostrophe`),
rangs de colonnes (1 à 60, dont `iban_column`), `negate`.

`RuleInput` : `label_contains`, `amount` (positif), `direction`
(`any|in|out`), `card_code` *ou* `account`, `ledger_id`, `position`,
`active`, `payee`.

== Événements

Abonnement : `entry.cancelled` (ligne de nouveau à traiter). Aucun
événement publié.
